# Real Android player integration

Run `npm run emulator` alongside `npm run dev`. The backend binds only to `127.0.0.1:4300`, reuses `emulator-5554`, and always invokes ADB with `ADB_MDNS=0`. The pinned official scrcpy 5.0.1 server streams H.264 video and handles touch, key and text input over its control socket. No launcher or store is simulated.

Host UI contract: iframe `/apps/emulator-viewer/index.html` inside the S26-inspired bezel. Use `allow="clipboard-read; clipboard-write"`, `title="Live Android emulator"`, full width/height and no border. The document contains the actual full Android display (including native system bars) and a 36px Back/Home/Recents control row. Do not add fake system bars. Player assets are served by the existing 4173 server; the player WebSocket connects directly to loopback4300. Direct standalone URL: `http://127.0.0.1:4300/`. Browser must support H.264 WebCodecs; Chromium is the tested target.

Pointer drag produces real touch down/move/up; wheel scroll produces a swipe; keyboard characters, paste, Enter, Backspace, arrows, Escape/Back and Home are forwarded to Android. Click the display to focus keyboard input. Navigation buttons operate the real system. Stream is capped at30fps and1200px long edge; unchanged screens naturally emit fewer frames. UI reports observed render FPS, not a promised rate.

`GET http://127.0.0.1:4300/health` reports ready state, received frame/byte counts and client count. Inside the player, `window.androidMetrics` exposes rendered frame count, observed FPS, input round-trip acknowledgement time and input-to-next-frame time. The latter is approximate and does not prove a semantic screen change. Backend rejects WebSocket origins other than localhost4173/4300; it exposes no arbitrary shell commands. H.264 packet framing and control protocol follow the pinned official scrcpy server: https://github.com/Genymobile/scrcpy/blob/v5.0.1/doc/develop.md . Vendor server is Apache2.0, license included. No audio stream.

Pointer repair: this player document disables selection only inside its own iframe, prevents pointer defaults, captures pointer movement, clamps coordinates to the rendered Android canvas, and releases touch on up/cancel/lost capture/blur. Host should also apply `user-select:none; -webkit-user-select:none` to its bezel/iframe wrapper. If a drag still highlights web page text, inspect iframe.src: it must be this live player, not the old `#home` mock phone/store route.
